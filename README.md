# Turbo — 用 Token 换速度

ZCode / Codex 并行加速 Skill：激活后以「并行优先」策略执行当次任务，宁可大量消耗 token，也要把总耗时压到最低。

## 初衷：白嫖模型的时候，也要萌萌干活

写这个 Skill 的起因很朴素：**用白嫖来的免费/低价模型时，更要把活干得又快又好。**

- 免费额度的模型，token「不要钱」——那就别让它闲着、别让它慢悠悠地串行磨洋工。
- 白嫖 ≠ 白给。恰恰是蹭来的模型，才应该火力全开：一次能并行发的调用全发出去，能同时派的子代理全派出去，把总耗时压到最短。
- 对付费模型同样适用：你已经决定「不计成本换速度」时，本 Skill 就是那条执行纪律。

一句话：**Token 不是约束，时间才是。白嫖的模型，也要萌萌干活。**

## 怎么实现

核心思路：**耗时主要来自串行等待**——一次只发一个工具调用、一步步等结果。把互不依赖的工作同时发出，总耗时约等于最慢的那一路，而不是所有步骤之和。

代价是更多 token（子代理各自持有上下文、存在重复读取）。本模式明确接受这一代价，不需要为省 token 而放慢节奏。

### 四级并行阶梯

按任务规模选择层级；两种做法都能完成时，选并行度更高的那种。只要仍有可并行的独立工作未被消化，就必须留在并行路径上。

| 层级 | 做法 | 典型场景 |
|------|------|----------|
| **L1 同消息并行工具调用** | 互不依赖的 Read / Grep / Glob / Bash 在同一条消息里全部发出，禁止「发一个、看结果、再发下一个」 | 读 3 个文件 + 搜 2 个关键词 → 一条消息发 5 个调用，而不是 5 轮 |
| **L2 预取** | 接到任务第一反应：把所有**可能**相关的文件立刻并行读入，不等第一轮结论再决定下一步看什么；等待某一路结果期间，同步预取后续材料 | 宁可多读，不要多等 |
| **L3 子代理扇出** | 任务可拆出 ≥2 个独立子任务时，单条消息并发派发多个 Agent：只读探索 → Explore；需要写文件 → 先按文件/目录分区，再并发派发 general-purpose | 调研 A、B、C 三个互不相关的主题 → 一条消息派 3 个子代理 |
| **L4 动态工作流** | 大型多文件、多阶段、可流水线化的任务 → 用 CreateWorkflow 编排高并发子代理执行 | 多模块重构、批量生成类任务 |

### 判定流程（每次任务开始时执行）

```
接到任务
 ↓ 拆依赖图：哪些子任务互不依赖？
 → 无依赖部分：立即并行（按规模选 L1/L3/L4）
 → 有依赖部分：按序执行；等待期间预取后续材料（L2）
 ↓ 全部返回
 → 合并、去重、指出冲突，再继续
```

### 铁律（正确性永远优先于速度）

违反以下任何一条的「并行」都是错误的，宁可串行：

1. **依赖必须按序** —— 后一步依赖前一步结果时禁止并行
2. **写操作必须分区** —— 两个执行体不得修改同一文件；无法分区就串行写
3. **结果必须汇总** —— 合并去重后再继续，冲突必须显式指出，不得默默随机取舍

### 豁免（不并行）

并行本身有开销（子代理上下文构建、结果合并）。以下情形正常执行，不扇出：

- 纯聊天问答，全程不需要工具调用
- 单一原子操作：改一行、看一个文件、回答一个只涉及单个文件的问题

## 安装

把本仓库目录（或其中的 `SKILL.md`）放到你的 skills 目录下，例如：

```text
~/.agents/skills/turbo/SKILL.md
```

ZCode 中位于 `C:\Users\<用户名>\.agents\skills\turbo\SKILL.md`。

## 触发方式

- **自动触发**：说出「太慢了」「加速」「快点」「并行处理」「别磨叽」「用 token 换速度」「不计成本」「不计任何成本」「不计成本消耗」「别省 token」「随便花 token」「token 无所谓」「成本无所谓」「火力全开」「全速」「turbo」等话术，或以任何方式表达「不在乎 token/成本消耗、只要快」的意思时立即激活，无需二次确认。
- **兜底规则**：话术中含有「不计成本 / 不计消耗 / 随便花 / 别省」等不设成本上限的语义，一律按本技能执行。
- **手动激活**：`/turbo`

## 汇报要求

并行执行结束后，用一两句话说明开了几路并行、省掉了哪些串行等待——让用户知道 token 花在了哪里。
